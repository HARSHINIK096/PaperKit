1. Problem Identification & The Stranger Trust Paradox
--------------------------------------------------------------------------------
1.1 The Context & The Crisis in Document Processing
In the modern digital workspace, Portable Document Format (PDF) files, scanned 
records, and office documents serve as the global standard for legal contracts, 
medical reports, financial audits, academic research, and government identification. 
However, the existing ecosystem of document utilities presents a fundamental 
security and operational dilemma known as The Stranger Trust Paradox:

  Stranger Trust Paradox = Need for High-Utility Document Operations 
                           <==> Mandatory Surrender of Confidential Data 
                                to Untrusted 3rd-Party Cloud Servers

1.2 Core Manifestations of the Problem:
- Data Exfiltration & Privacy Leakage: Commercial web-based PDF converters 
  require users to upload unencrypted, sensitive files (containing Personally 
  Identifiable Information [PII], PAN, SSN, bank statements, proprietary code, 
  and trade secrets) to opaque remote servers with unknown retention policies.
- Bandwidth & Latency Inefficiencies: Simple operations like merging 3 PDFs, 
  reordering pages, rotating scans, or adding watermarks should take milliseconds. 
  Instead, cloud-only workflows incur network round-trips (Upload -> Server Queue 
  -> Processing -> Download), making document handling tedious on mobile networks.
- Fragile Cloud Dependency & Zero Offline Utility: When mobile workers, 
  researchers, or students are offline, in air-gapped secure labs, or in low-
  connectivity areas, web-dependent tools are completely unusable.
- AI Hallucinations & Lack of Grounding: Generic cloud LLM interfaces lack spatial 
  PDF layout grounding, rendering them incapable of extracting tabular data, 
  verifying digital signatures, or sanitizing confidential metadata.


2. Abstract & Research Summary
--------------------------------------------------------------------------------
PaperKit is a dual-tier, open-source document engineering and intelligence platform 
designed to eliminate the Stranger Trust Paradox through a hybrid Zero-Latency 
Client-Side Native Engine paired with a Hardened Backend AI & Media Processing 
Architecture. Built with a native Flutter/Dart frontend and a FastAPI/PyMuPDF 
backend, PaperKit guarantees complete data sovereignty by executing 90% of 
sensitive PDF manipulations (merging, splitting, compressing, watermarking, password 
encryption, metadata stripping, page organization, and digital signing) entirely 
on the client device in 0 ms without internet access.

For compute-heavy tasks (bi-directional OpenXML document conversions, Multimodal 
Vision OCR, semantic document RAG, automated PII redaction, and media transcoding), 
PaperKit uses an isolated, memory-safe backend pipeline with ephemeral storage 
auto-purging, cryptographic validation, and multi-model fallbacks (Groq Vision + 
Google Gemini Flash).


3. Objectives & Scope of the Project
--------------------------------------------------------------------------------
3.1 Primary Objectives:
- Zero-Knowledge Local Execution: Implement client-side PDF parsing, rendering, 
  and manipulation engines running locally on the user's mobile device.
- 256-Bit Cryptographic Security & Privacy: Provide local AES-256 password 
  protection, irreversible text redaction, metadata scrubbing, and digital 
  signature placement with coordinate precision.
- Universal Multi-Format Document Conversion: Facilitate bidirectional format 
  transformations between PDF, Word (.docx), Excel (.xlsx), PowerPoint (.pptx), 
  Images, Markdown, and TXT.
- Multimodal AI Document Intelligence: Deliver fast OCR, semantic search, document 
  comparison, tabular extraction, and conversational RAG querying.
- Offline-First Resilience: Ensure complete functionality of core utilities 
  without network availability.

3.2 Scope of the System:
- In-Scope: Full Flutter-native mobile app (Android/iOS), FastAPI Python 
  microservice backend, 37+ specialized tools, ephemeral memory cleanup.
- Out-of-Scope: Closed-source proprietary cloud lock-in, persistent storage of 
  unencrypted raw user documents on public cloud databases.

4.2 Critical Limitations in Prior Art:
1. Data Leakage Vectors: Server-side conversion queues retain intermediate 
   unencrypted artifacts in temp directories.
2. High Memory Overhead: Existing mobile viewers deserialize full PDF bitmaps 
   into RAM, causing out-of-memory (OOM) crashes on large files (>100 pages).
3. Inability to Edit Without Reflow Distortion: Traditional editors disrupt font 
   glyph metrics when attempting in-place modifications.

7. Advantages & Mathematical Innovation (SHARP)
--------------------------------------------------------------------------------
PaperKit implements the SHARP framework (Spatial Hashing & Adaptive Redaction 
Protocol) for document precision:

7.1 Mathematical Foundation of Spatial Redaction & Glyph Alignment:
Coordinates are normalized in dimensionless Euclidean 2D space:
  x_norm = x_canvas / W_canvas,   y_norm = y_canvas / H_canvas
  x_pdf  = x_norm * W_pdf_pt,     y_pdf  = (1.0 - y_norm) * H_pdf_pt

For irreversible redaction, the bounding rectangle matrix R is transformed:
  R_redact = [[x0, y0], [x1, y1]] such that integral(I_original(x, y)) -> 0

  S - Spatial Coordinate Precision    : Sub-pixel glyph bounding box mapping
  H - Hybrid Execution Stratum        : 0ms client execution + fallback AI cloud
  A - Adaptive Redaction Pipeline     : Irreversible PII vector scrubbing
  R - Resilient Offline Operation     : Fully functional without active network
  P - Privacy-First Ephemeral Storage : Guaranteed automated storage purge


8. Detailed Module Description
--------------------------------------------------------------------------------
1. PDF Core Engine (pdf_tools):
   - MergePDFScreen: Multi-document concatenation preserving page trees.
   - SplitPDFScreen: Range splitting, interval splitting, or single-page bursting.
   - CompressPDFScreen: Downsampling image streams and unreferenced XObjects.
   - PDFEditorScreen: In-place text line extraction and canvas object editing.
2. Security & Cryptography Suite (security_tools):
   - ProtectPDFScreen: 256-bit AES password encryption with permission flags.
   - SmartRedactionScreen: Irreversible text and PII redaction.
   - DigitalSignatureScreen: Interactive drag-and-drop signature stamping.
   - MetadataScreen: Inspects and wipes EXIF/author/creator metadata.
3. Image & Media Engine (image_media_tools):
   - ImageConverterScreen: High-speed format conversion (PNG, JPG, WEBP, BMP, GIF).
   - VideoConverterScreen & AudioConverterScreen: Native FFmpeg transcoding.
   - MediaDownloaderScreen: Audio/video extraction from YouTube and Spotify.
   - ArchiveStudioScreen: Client-side ZIP/TAR archive creation & extraction.
4. AI Document Intelligence Suite (ai_tools):
   - OCRScreen: Multimodal Vision OCR extraction.
   - SummarizePDFScreen: AI summary generation (concise, bullets, action items).
   - AskPDFScreen: RAG-based interactive question-and-answer interface.
   - SemanticCompareScreen: Detects textual, financial, and structural shifts.
   - SimilarityMatrixScreen: Multi-document pairwise similarity calculation.

11. Implementation Details & Cryptographic Pipeline
--------------------------------------------------------------------------------
11.1 Client-Side 256-Bit AES Encryption Implementation (Dart):
- Instantiates PdfDocument from raw file bytes.
- Configures PdfEncryptionAlgorithm.aesx256Bit with user & owner passwords.
- Applies granular permission flags (print, copyContent).
- Saves directly to local application storage.

11.2 Backend Universal Request Normalizer & Fallback (Python):
- Safely extracts multipart form-data or JSON payloads.
- Validates PDF binary headers (%PDF-).
- Automatically triggers Multimodal Vision OCR if digital text stream is empty.
